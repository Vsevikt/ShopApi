1. Перший Admin створюється під час початкового запуску системи через AdminSeeder. Пароль зберігається в БД тільки в хешованому вигляді.

2. Користувач створюється через основний endpoint реєстрації і за замовчуванням отримує роль User. Для створення нового Admin або Moderator окремий користувач не створюється, існуючому користувачу Admin через захищений endpoint змінює роль. Роль зберігається як enum UserRole. Endpoint зміни ролі доступний тільки Admin.

3. Відновлення пароля працює через email. Admin або Moderator вказує email користувача, система створює одноразовий PasswordResetToken з терміном дії та надсилає користувачу посилання на email. Користувач переходить за посиланням і вводить новий пароль. Backend перевіряє токен, хешує новий пароль через BCrypt, зберігає його та робить токен недійсним.

RefreshToken для цього не використовується, тому що він призначений для отримання нового AccessToken, а PasswordResetToken саме для відновлення пароля.
